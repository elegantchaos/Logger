# Review Logger #34

## Summary

Reviewed [PR #34](https://github.com/elegantchaos/Logger/pull/34) at
`f9682990a3f80ca950a423b361241130d8fbda73`, against `origin/main`.
The change integrates Bookish's CI/package maintenance, removes the empty
LoggerTestSupport product, and adds the shared agent baseline. Verdict: ready
after fixes. The removal preserves active logging code and test coverage, but
the workflow can report success without validating an Apple platform.

## Findings

1. **Should fix, P2: platform setup failures become passing checks.**
   `.github/workflows/tests.yml:364-367` turns a failed `xcodebuild
   -showdestinations` into `exit 0`; the test at lines 403-404 then skips because
   `available` remains false. The same pattern covers simulator connection,
   downloads and boot failures across all six Apple simulator jobs. A scratch
   execution of the actual iOS selection script, with successful simulator
   discovery and `xcodebuild` returning 65, returned zero and wrote
   `available=false`. This can hide package or scheme regressions as simulator
   availability problems. Fail on discovery/build-configuration errors; make
   any deliberately optional infrastructure skips explicit and ensure required
   platform validation cannot finish green without its build/test step.

2. **Should fix, P3: removed product retains an unusable shared scheme.**
   `.swiftpm/xcode/xcshareddata/xcschemes/LoggerTestSupport.xcscheme:17` still
   names the deleted target, and `Logger-Package.xcscheme:45` retains it in its
   build list. Running `xcodebuild -workspace . -scheme LoggerTestSupport
   -destination 'generic/platform=macOS' -derivedDataPath
   .build/tmp/pr34-xcode build` outside the sandbox failed with exit 66:
   "Scheme LoggerTestSupport is not currently configured for the build action."
   Delete the standalone scheme and remove its package-scheme entry. The main
   package scheme still builds successfully, so this is cleanup of a broken
   selectable scheme, not evidence that the main package build fails.

3. **Should fix, P3: the assertion simplification violates Swift Testing guidance.**
   `Tests/LoggerTests/LoggerUITests.swift:30` changes an explicit false
   comparison to `#expect(!watcher.channels[0].isEnabled)`. The required
   Swift Testing core rules specifically retain explicit false comparisons
   because negated operands can produce misleading failure diagnostics.
   Restore `#expect(watcher.channels[0].isEnabled == false)`. Truth conditions
   and passing-test coverage are unchanged.

4. **Suggestion, P3: generated workflow has unresolved lint findings.**
   `actionlint .github/workflows/tests.yml` exits 1 with twelve ShellCheck
   SC2012 informational findings, two in each Xcode-resolution script beginning
   at lines 200, 459, 892, 1151, 1410 and 1669. Replace the `ls` pipelines with
   robust path enumeration in the generator and regenerate, or document an
   appropriately narrow suppression. These findings do not establish a failure
   with today's runner application names.

removed consistently from the manifest and active test source. Scheme cleanup
remains, as described above. Root Package.resolved is unnecessary with no
package dependencies. Historical examples retain their own dependency pins.

Checked: searched code, hidden configuration, examples, docs and scripts for
LoggerTestSupport, LoggerKit, ActionBuilder and ChaosTesting; read deleted
files, all four changed schemes and both manifests used by examples/package.

### Simplification Now Possible

`pick_destination()` has six definitions and no callers after the new selection
steps adopt `pick_destination_if_available()`. Remove it in the workflow
generator. Obsolete LoggerKit/LoggerKitTests scheme references also remain from
before this change and can be cleaned up with the scheme work.

Checked: searched workflow function declarations/calls, compared the previous
combined Apple job with all six replacement jobs, and matched scheme target
names against Package.swift.

### Duplication

Six jobs repeat Xcode resolution, destination parsing, simulator booting and
skip policy. Two Linux/macOS versions also repeat nearly identical commands.
Generated output explains the repetition, but the generator should own fixes
and regression checks so copies cannot drift. No new runtime-library
duplication was introduced.

Checked: read the complete workflow, its generation header, old workflow,
package dependency graph and existing `.bin`/VS Code task entry points.

### Design Clarity

Removing an empty published product and documenting a v3 release is coherent.
Removing the unused ActionBuilderPlugin dependency also removes its transitive
consumer build cost. The logging API and persistence behavior are unchanged.
The new CI skip policy weakens the meaning of a successful platform check and
needs an explicit validation contract.

Checked: PR body and commits; README, AGENTS.md and complete journal; settings
protocol/implementation, Manager defaults, Channel logging and the watcher
adapter exercised by the changed test. No decision log exists.
